The library rule The subject forbids libraries that “do all the work” (e.g. numpy.polyfit). The mandatory files import only the Python standard library: csv, json, math, os, pathlib, argparse, sys. No numpy, no pandas, no scikit-learn. matplotlib is used only in plot.py to draw dots and a line; it computes nothing. You can prove it in the defense with: 
grep -n "import" *.py

How the pieces connect

model.py: the shared foundation

estimate_price: the hypothesis

def estimate_price(mileage: float, theta0: float, theta1: float) -> float:
    """The hypothesis given by the subject, written exactly as specified."""
    return theta0 + (theta1 * mileage)

This one line is the whole “model”. It is written exactly as in the subject so the evaluator can match it at a glance. Both train.py and predict.py call this same function. The subject asks for this: “the estimatePrice is the same as in our first program”.

parse_number: safe conversion

Python's float() accepts "nan", "inf" and "1e400" (which becomes inf). None of these is a valid mileage or price, so parse_number rejects anything that is not finite with math.isfinite, and turns ValueError into our own ModelError with a readable message.

ModelError: one error type for the user

Every expected problem (missing file, bad row, corrupt thetas) raises ModelError. Each program's main() catches it, prints Error: … on stderr and returns exit code 1. So the user never sees a Python traceback for a predictable mistake, which evaluators often test.

load_dataset

  • Uses the csv module rather than line.split(","), so quoted fields and Windows line endings work.
  • Skips blank lines, requires a 2-column header, and checks that every row has 2 finite numbers. Errors give the line number: Error: line 5: 'abc' is not a number.
  • Column names are read from the header, not hard-coded. The subject says the algorithm should work “with any other dataset”: any CSV with a feature column and a target column works.

load_thetas / save_thetas

if not path.exists():
    return 0.0, 0.0, False      # untrained: the subject says thetas start at 0
  • No file means not trained, so both thetas are 0, as the subject requires (“Before running the training program, theta0 and theta1 will be set to 0”).
  • A corrupt file is an error, not silently 0. Silently using 0 would hide a real problem.
  • JSON format ({"theta0": …, "theta1": …}): readable by a human and parsed by the standard library.
  • Atomic save: write to thetas.json.tmp, then os.replace it over the real file. If the program crashes mid-write, the old file is still intact.

train.py: the learning program

gradient_descent: the core of the project

for _ in range(iterations):
    sum_errors = 0.0
    sum_errors_times_mileage = 0.0
    for i in range(m):
        error = estimate_price(mileages[i], theta0, theta1) - prices[i]
        sum_errors += error
        sum_errors_times_mileage += error * mileages[i]

    tmp_theta0 = learning_rate * (1 / m) * sum_errors
    tmp_theta1 = learning_rate * (1 / m) * sum_errors_times_mileage

    # Simultaneous update: both tmp values above were computed with the
    # OLD theta0 and theta1. Only now do we change them.
    theta0 = theta0 - tmp_theta0
    theta1 = theta1 - tmp_theta1

Line by line:

  1. The inner loop goes over i = 0 … m−1, which is the Σ in the subject.
  2. error is estimatePrice(mileage[i]) − price[i], computed with the current thetas.
  3. The two highlighted lines are the subject's formulas word for word, including the (1 / m).
  4. Both tmp values are computed before either theta changes. That is the simultaneous update.
  5. We subtract, because the gradient points uphill and we want to go down.

The loops are written in plain Python on purpose, without vector tricks, so the evaluator sees the formula directly. With 24 rows × 1 000 iterations it takes milliseconds.

Divergence detection

current_cost = cost(mileages, prices, theta0, theta1)
if not (math.isfinite(theta0) and math.isfinite(theta1) and math.isfinite(current_cost)):
    raise DivergenceError(...)

With a too-large learning rate, the thetas grow until they become inf or nan. Without this check, train.py would save NaN to thetas.json and predict.py would print nan. We stop and explain instead, and nothing is saved.

A real bug the tests caught cost uses error * error, not error ** 2. In Python, float ** 2 raises OverflowError on overflow, while float * float returns inf. The first version used ** 2 and crashed with a traceback when training diverged. The test test_train_reports_divergence_cleanly found it.

cost

J = (1/2m) Σ error². It is not needed to compute the update; the update only uses the derivatives. We compute it to print progress (“Cost: 20880519.29 → 222822.62”), to detect divergence, and for the tests that check the cost never increases.

standardize and denormalize

scaled, mean, std = standardize(mileages)                 # x' = (x - mean) / std
theta0_n, theta1_n, history = gradient_descent(scaled, prices, lr, iterations)
theta0, theta1 = denormalize(theta0_n, theta1_n, mean, std)  # back to raw km

See Concepts §5 for the maths. Note the guard in standardize: if every mileage is identical, σ = 0 and we would divide by zero. More importantly, a line through points that all share the same x is undefined, so we report that clearly.

mean_and_std uses the population standard deviation (divide by m). Dividing by m−1 (the sample version) would also work, because the conversion back undoes whichever σ we used.

predict.py: the prediction program

theta0, theta1, trained = load_thetas(args.thetas)
if not trained:
    print("Note: model not trained yet, using theta0 = 0 and theta1 = 0.")
mileage = ask_mileage()
price = estimate_price(mileage, theta0, theta1)
print(f"Estimated price for {mileage:g} km: {price:.2f}")

The subject: “When you launch the program, it should prompt you for a mileage, and then give you back the estimated price.” So it prompts with input(); the mileage is not a command-line argument.

Input handling in ask_mileage

InputResult
abc, empty line, nan, inf, 1e400“Invalid mileage: …” and ask again
-5“it cannot be negative” and ask again
0, 42000, 1.5e5, 80000 accepted (spaces are stripped)
Ctrl+D (EOF)clean exit, code 1, no traceback
Ctrl+Cclean exit, code 130 (the shell convention for SIGINT)

A very large mileage gives a negative price. We still print the number, because that is what the hypothesis says, and add a warning that it is outside the data. Hiding it or clamping it to 0 would mean not using the specified hypothesis.

Bonus programs

precision.py

compute_metrics builds the error list once and derives MAE, MSE, RMSE and R² by hand. The edge case where every price is identical (R²'s denominator is 0) is handled explicitly. See Concepts §6 for what each metric means.

plot.py

Scatter of the data, plus the line from thetas.json. A straight line needs only two points, so we compute estimate_price at the min and max mileage and join them. --save plot.png writes a file instead of opening a window, which is useful over SSH or without a display. matplotlib is imported inside main() after the arguments are parsed, so --help stays fast.

The tests

Run with uv run pytest -v. The most important ones:

TestWhat it proves
test_gradient_descent_matches_closed_form_on_project_dataOur trained thetas equal the exact least-squares answer (θ1 = cov/var) to 6 significant digits. Gradient descent really found the minimum.
test_first_step_uses_subject_formula…One step from (0, 0) gives exactly what the subject's formula gives by hand.
test_second_step_uses_old_thetas_for_both_gradientsThe simultaneous update: the second step uses old thetas for both gradients. A sequential-update bug fails this test.
test_cost_never_increases_with_small_learning_rateEach step goes downhill.
test_predict_before_training_gives_zeroThe subject rule: before training, the prediction is 0.
test_train_reports_divergence_cleanlyA bad learning rate gives a message, not a traceback, and no file is written.
test_bad_datasets_raise_model_errorSeven kinds of broken CSV are all rejected cleanly.

The closed-form formula appears only in the tests, as an independent referee. Using it in train.py would break the subject's rule that training must use gradient descent.

uv in two minutes

  • pyproject.toml declares the dependencies (matplotlib for the bonus, pytest in the dev group).
  • uv.lock pins the exact versions, so every machine installs the same thing.
  • uv sync creates .venv/ and installs from the lock file.
  • uv run script.py runs the script inside that environment, with no manual activation needed.
  • package = false tells uv this is a set of scripts, not an installable library.

The Makefile

42 projects ship a Makefile with the rules all, clean, fclean and re. Here they map onto uv:

all: $(VENV)
$(VENV): pyproject.toml uv.lock     # rebuilt only if these files change
	$(UV) sync
	@touch $(VENV)
  • No relink: .venv is a real file target that depends on pyproject.toml and uv.lock. Running make twice prints “Nothing to be done for 'all'”. Evaluators check this. touch updates the folder's timestamp, because uv sync does not always change it.
  • clean removes caches (__pycache__, .pytest_cache) and temporary files. fclean also removes .venv and thetas.json, which puts the model back to untrained (θ = 0), the equivalent of deleting the binary in a C project.
  • The run rules (train, predict, …) depend on $(VENV), so dependencies are installed first if needed. ARGS passes options through: make train ARGS="--iterations 200".
  • Every rule that is not a file is listed in .PHONY, so a file named test or clean can never block it.
