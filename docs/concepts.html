1What is machine learning?

The subject quotes Tom Mitchell:

“A computer program is said to learn from experience E with respect to some class of tasks T and performance measure P, if its performance at tasks in T, as measured by P, improves with experience E.”

For this project:

LetterMeaningIn ft_linear_regression
Tthe taskpredict the price of a car from its mileage
Ethe experiencethe 24 (mileage, price) examples in data.csv, seen over and over during training
Pthe performance measurethe cost J (mean squared error). Lower is better.

Before training, θ0 = θ1 = 0 and every prediction is 0, so the cost is huge (about 20.9 million). After 1 000 steps of training the cost is about 222 823. Performance improved with experience, so by Mitchell's definition the program learned.

Vocabulary

  • Supervised learning: every training example has the right answer (the price). The program learns to map input to answer.
  • Regression: the answer is a continuous number. (Classification would be a category, like “cheap / expensive”.)
  • Feature (input, x): the mileage. We have exactly one feature, so this is simple (univariate) linear regression.
  • Target (label, y): the price.
  • Parameters (weights): θ0 and θ1, the numbers the program learns.
  • m: the number of training examples. The subject says “I let you guess what m is”. It is the number of data rows: m = 24.

2The hypothesis: a straight line

The subject imposes this function:

estimatePrice(mileage) = θ0 + (θ1 × mileage)

It is the equation of a straight line, the same as y = b + ax from school:

  • θ0, the intercept: the predicted price when mileage = 0. The point where the line crosses the vertical axis. Unit: price.
  • θ1, the slope: how much the price changes for each extra kilometre. Negative here, because cars lose value as they are driven. Unit: price per km.

After training we get θ0 ≈ 8 499.60 and θ1 ≈ −0.021449. Read it as: “a car with 0 km would cost about 8 500, and it loses about 21.45 for every 1 000 km driven.” So for 100 000 km: 8 499.60 − 0.021449 × 100 000 ≈ 6 354.70.

Training is a search Every possible pair (θ0, θ1) is a different line. Training means finding the pair whose line fits the data best. To search, we first need a number that says how good a line is. That is the cost function.

3The cost function: how wrong is a line?

For each example i, the error (residual) is the difference between the prediction and the truth:

errori = estimatePrice(mileagei) − pricei

In the figure below the dashed lines are these errors for a line drawn by hand (θ0 = 8 000, θ1 = −0.015). A good line keeps them short.

To get one number for the whole dataset, we square each error and take the average. That is the mean squared error. We also divide by 2, which makes the derivative cleaner (see §4):

J(θ0, θ1) = 12m Σi=0m−1 ( estimatePrice(mileagei) − pricei )2

Why square the errors?

  1. Signs would cancel. An error of +1 000 and one of −1 000 add up to 0, which would look like a perfect line. Squaring makes every error positive.
  2. Big errors count more. An error of 2 000 costs 4× more than one of 1 000, so the line will not ignore points that are far off.
  3. It is smooth. Unlike absolute value, a square has a derivative everywhere. Gradient descent needs that.
  4. One minimum, no traps. For linear regression, J is a “bowl” (convex). There is exactly one lowest point and no local minimum to get stuck in.
Worked example: the cost for the first 3 rows

Rows: (240 000, 3 650), (139 800, 3 800), (150 500, 4 400). Here m = 3.

J(0, 0): every prediction is 0, so the errors are −3 650, −3 800, −4 400. Squares: 13 322 500 + 14 440 000 + 19 360 000 = 47 122 500. Divide by 2m = 6: J ≈ 7 853 750.

J(8 000, −0.02): predictions are 3 200, 5 204, 4 990. Errors are −450, +1 404, +590. Squares: 202 500 + 1 971 216 + 348 100 = 2 521 816. Divide by 6: J ≈ 420 303. A much better line.

4Gradient descent: walking downhill

The intuition

Picture the cost J as a landscape. Each position (θ0, θ1) has a height J. You stand somewhere on a hill in fog and want to reach the bottom of the valley. You cannot see the valley, but you can feel the slope under your feet. So: take a small step in the steepest downhill direction, then repeat. That is gradient descent.

The one bit of calculus you need

The derivative of a function is its slope: how much the output changes when you nudge the input a tiny bit. A partial derivative ∂J/∂θ0 is the slope in the θ0 direction while θ1 is held still. The two partial derivatives together form the gradient, which points uphill.

Two rules are enough:

  • Power rule: the derivative of u2 is 2u.
  • Chain rule: the derivative of f(g(θ)) is f′(g(θ)) × g′(θ). In words: the derivative of the outside times the derivative of the inside.

Deriving the subject's formulas

Write ei = θ0 + θ1·xi − yi for the error on example i, so J = (1/2m) Σ ei2.

The inside, ei, depends on the thetas like this:

  • ∂ei/∂θ0 = 1 (θ0 is added once)
  • ∂ei/∂θ1 = xi (θ1 is multiplied by xi)

Chain rule on ei2: the outside gives 2ei, times the inside's derivative. The 2 cancels with the ½:

∂J∂θ0 = 12m Σ 2·ei·1 = 1m Σ ei      ∂J∂θ1 = 1m Σ ei·xi

Multiply each by the learning rate and you have exactly the formulas in the subject:

tmpθ0 = learningRate × 1m Σi=0m−1 (estimatePrice(mileagei) − pricei)
tmpθ1 = learningRate × 1m Σi=0m−1 (estimatePrice(mileagei) − pricei) × mileagei

tmpθ is “learning rate × gradient”. The update moves against the gradient, because the gradient points uphill:

θ0 := θ0 − tmpθ0     θ1 := θ1 − tmpθ1 The subject does not write this line, but it is what “update theta0 and theta1” means in gradient descent.
Sanity check with intuition Suppose every prediction is too high (all errors positive). Then Σe > 0, so tmpθ0 > 0 and θ0 goes down. The line moves down towards the data. Correct.

The learning rate (α)

The learning rate is the size of each step.

  • Too small: each step barely moves. You need a huge number of iterations.
  • Good: the cost drops quickly and then flattens out (converges).
  • Too large: you jump over the bottom of the bowl, land higher on the other side, and each jump gets bigger. The cost grows to infinity (divergence). train.py detects this and stops with an error message.

With our normalized data, any learning rate between 0 and 2 converges. We use 0.1 with 1 000 iterations. It reaches the optimum after about 200 steps, so 1 000 leaves a wide safety margin. Try different values in the Playground.

Simultaneous update

The subject insists: “don't forget to simultaneously update theta0 and theta1”. Both gradients must be computed from the same old (θ0, θ1). The wrong way:

# WRONG: theta1's gradient sees the NEW theta0
theta0 = theta0 - lr * mean(errors(theta0, theta1))
theta1 = theta1 - lr * mean(errors(theta0, theta1) * x)   # <- theta0 already changed!

# RIGHT: compute both tmp values first, then assign
tmp_theta0 = lr * mean(errors(theta0, theta1))
tmp_theta1 = lr * mean(errors(theta0, theta1) * x)
theta0 = theta0 - tmp_theta0
theta1 = theta1 - tmp_theta1

The wrong version is no longer gradient descent: it is a different algorithm with different convergence behaviour. That is why the subject calls the values tmpθ.

Why start at 0?

The subject requires θ0 = θ1 = 0 before training. Because J is a bowl with a single minimum, the starting point does not change the final answer. It only changes how many steps it takes.

Batch vs stochastic gradient descent

We use batch gradient descent: each step uses all m examples (the Σ from 0 to m−1). Stochastic gradient descent uses one example per step, and mini-batch uses a small group. They are faster on huge datasets but noisier. With 24 rows, batch is the natural choice, and it is what the subject's formulas describe.

5Feature scaling: why we normalize mileage

The problem

Mileage goes up to 240 000. Price is around 3 650 to 8 290. Look at the two gradients:

  • ∂J/∂θ0 = mean(error), a number about the size of a price.
  • ∂J/∂θ1 = mean(error × mileage), about 100 000 times bigger, because each term is multiplied by a mileage.

The same learning rate is used for both. If α is small enough for θ1 not to explode (around 10−10), θ0 moves by about 10−6 per step and would need billions of steps to reach 8 500. If α is big enough for θ0, θ1 explodes. Geometrically, the bowl is stretched into an extremely narrow valley and gradient descent zig-zags between its walls.

Try it uv run train.py --no-normalize --learning-rate 0.01 diverges. uv run train.py --no-normalize --learning-rate 1e-10 runs, but gives θ0 ≈ 0.0002 and θ1 ≈ +0.045: a positive slope, which is completely wrong. θ1 was forced to fit the data on its own because θ0 could not move.

The fix: standardization

Before training, rescale the mileage so it has mean 0 and standard deviation 1:

x′ = x − μσ μ = mean mileage ≈ 101 066 km, σ = standard deviation ≈ 51 565 km (computed from the dataset)

Now x′ is roughly between −1.5 and +2.7, so both gradients have similar sizes and one learning rate works for both. We run the exact same gradient descent on (x′, price) and get thetas for the scaled input: θ′0 ≈ 6 331.83 and θ′1 ≈ −1 106.02.

Converting back to raw kilometres

predict.py must use the subject's hypothesis on raw mileage, so we convert the thetas. Substitute x′ into the line and expand:

price = θ′0 + θ′1 · x − μσ = (θ′0 − θ′1·μσ) + (θ′1σ) · x

Match it with θ0 + θ1·x:

θ1 = θ′1 / σ     θ0 = θ′0 − θ′1 · μ / σ

Check: θ1 = −1 106.02 / 51 565.19 ≈ −0.021449 and θ0 = 6 331.83 + 1 106.02 × 101 066.25 / 51 565.19 ≈ 8 499.60.

The saved thetas are therefore the thetas of a normal line on raw km. predict.py needs no knowledge of μ or σ.

Is this allowed by the subject? Yes. The training formula, the simultaneous update and the hypothesis are all used exactly as written. Normalization only changes the units of the input fed to that formula, which is standard practice (the original Stanford course this project comes from teaches it as the next lesson). Be ready to explain it in the defense; it is the most common question.
Min-max scaling, the other common option

x′ = (x − min) / (max − min) puts every value between 0 and 1. It works too. The conversion back has the same shape with min instead of μ and (max − min) instead of σ. We chose standardization because it centres the data at 0. That separates the two gradients completely (see the next box) and gives a clean rule for the learning rate.

Advanced: why α < 2 converges, and α = 1 converges in one step

J is a quadratic function. Gradient descent on a quadratic is stable when α < 2/λmax, where λmax is the largest eigenvalue of its Hessian (matrix of second derivatives). The Hessian here is [[1, mean(x)], [mean(x), mean(x²)]].

  • With standardized x: mean(x′) = 0 and mean(x′²) = 1, so the Hessian is the identity. Both eigenvalues are 1, so any α < 2 converges. With α = 1, a single step lands exactly on the minimum (you can check: uv run train.py --learning-rate 1 --iterations 1).
  • With raw x: mean(x²) ≈ 1.29 × 1010, so α must be below about 1.55 × 10−10. The smallest eigenvalue is tiny, so θ0 barely moves. The ratio between the two eigenvalues (the condition number) is enormous.

6Measuring precision (bonus)

precision.py computes four standard metrics on the dataset. Our values after training:

MetricFormulaValueMeaning
MAE(1/m) Σ |ei|557.84On average a prediction is off by about 558.
MSE(1/m) Σ ei2445 645Same as 2 × J. Hard to read because the unit is price².
RMSE√MSE667.57MSE back in price units. Larger than MAE because big errors weigh more.
R²1 − Σe2 / Σ(y − ȳ)20.733The line explains 73% of the variation in prices.

Understanding R²

Compare our line with the dumbest possible model: always predict the mean price (ȳ ≈ 6 332). R² measures how much of that model's error we removed.

  • R² = 1: perfect, every point is on the line.
  • R² = 0: no better than predicting the mean every time.
  • R² < 0: worse than the mean. This is what you get before training (θ = 0 predicts 0 for every car).

0.733 is reasonable for one feature: mileage explains most of the price, and the rest depends on things we do not have (model, year, condition…).

RMSE ≥ MAE, always They are equal only when every error has the same size. The bigger the gap, the more the error comes from a few bad points. Here the gap is moderate: a few cars, such as the one at 139 800 km sold for 3 800, sit far below the line.
Honest caveat We measure precision on the same data we trained on. With more data, you would keep a separate test set the model never saw, so you measure how it does on new cars. With 24 rows, splitting would leave too little to learn from, so we report training-set metrics and say so.

7Limits of this model

  • Extrapolation. The data covers 22 899 to 240 000 km. At about 396 000 km the line crosses 0, and beyond that it predicts a negative price. predict.py prints a warning in that case. A line is only trustworthy near the data it learned from.
  • A real depreciation curve is not straight. Cars lose value fast early and slowly later. A line is a simplification.
  • Little data. 24 cars is very few. One unusual car moves the line noticeably.
  • One feature. Brand, age, fuel and condition all matter. Using several features is multivariate linear regression, the natural next step (DSLR and multilayer-perceptron build on these ideas).
  • Correlation, not causation. The model learns that high mileage goes with low price. It does not know why.
