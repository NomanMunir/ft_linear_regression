The basics

What is m?

The number of training examples, the rows in data.csv: 24. The subject's Σ goes from i = 0 to m − 1, so it covers every example.

What do θ0 and θ1 represent? What are their values and units?

θ0 is the intercept: the predicted price at 0 km, ≈ 8 499.60 (price units). θ1 is the slope: price change per km, ≈ −0.021449 (price per km). The car loses about 21.45 per 1 000 km.

Why are θ0 and θ1 set to 0 before training?

The subject requires it. Mathematically the starting point does not matter here: the cost is convex (a bowl), so gradient descent reaches the same minimum from anywhere. Only the number of steps changes.

Is this supervised or unsupervised? Regression or classification?

Supervised, because each example has its true price. Regression, because the output is a continuous number.

Explain the Mitchell definition for this project.

T = predicting price from mileage. E = the 24 examples. P = the cost (mean squared error). P improves from ~20.9 million to ~222 823 as the program trains on E, so it learns. §1

Gradient descent

What does gradient descent do, in one sentence?

It repeatedly moves the parameters a small step in the direction that decreases the cost fastest (the negative gradient) until the cost stops decreasing.

Where do the subject's formulas come from?

They are the partial derivatives of the cost J = (1/2m) Σ (θ0 + θ1·xᵢ − yᵢ)² with respect to θ0 and θ1, multiplied by the learning rate. The ½ cancels the 2 from the power rule; the chain rule adds a factor 1 for θ0 and xᵢ for θ1. Be ready to derive this on a whiteboard. §4

Why subtract tmpθ rather than add it?

The gradient points in the direction where the cost increases. We want to decrease it, so we go the opposite way.

What is the simultaneous update and why does it matter?

Both tmp values are computed from the same old θ0 and θ1, and only then are both thetas replaced. If you updated θ0 first and used the new θ0 to compute θ1's gradient, you would no longer be following the gradient at one point; it would be a different algorithm. In the code: the two tmp_theta lines come before both assignments. A test checks it.

What is the learning rate and what happens if it is too big or too small?

The step size. Too small: very slow convergence. Too big: each step overshoots the minimum further and the cost explodes (divergence). With our normalized data it converges for 0 < α < 2; we use 0.1. Our code detects divergence and stops with a message.

How do you know when to stop? Why 1 000 iterations?

When the cost stops changing meaningfully (convergence). With α = 0.1 the cost is flat after about 200 iterations; 1 000 is a comfortable margin and still runs in milliseconds. A tolerance-based stop (“stop when the cost changes by less than ε”) is a valid alternative.

Could gradient descent get stuck in a local minimum here?

No. The cost of linear regression with squared error is convex, so it has a single global minimum.

Is this batch, stochastic or mini-batch gradient descent?

Batch: each step uses all m examples, as in the subject's Σ from 0 to m − 1.

Feature scaling (the most common question)

Why do you normalize the mileage?

Mileages are around 100 000 while prices are around 6 000, so the θ1 gradient is ~100 000× larger than the θ0 gradient. One learning rate cannot suit both: small enough for θ1 means θ0 never moves; big enough for θ0 makes θ1 explode. Standardizing (x − μ)/σ puts the input on a scale around ±2, so a single learning rate works. Demo: uv run train.py --no-normalize --learning-rate 1e-10 gives a wrong, positive slope.

Doesn't normalizing break the “use the specified training function” rule?

No. The update formula is applied exactly as written, with the same estimatePrice and simultaneous update. Only the input values are rescaled first. The thetas are then converted back, so predict.py uses the subject's hypothesis on raw km.

How do you convert the thetas back? Derive it.

price = θ′0 + θ′1·(x − μ)/σ = (θ′0 − θ′1·μ/σ) + (θ′1/σ)·x. So θ1 = θ′1/σ and θ0 = θ′0 − θ′1·μ/σ. See denormalize in train.py and §5.

Why not also normalize the price?

It is not needed: only the mismatch between the two gradients causes trouble, and that comes from the mileage. Normalizing the price too would also work, but then you would need a second conversion step.

Results and limits

How do you know your result is correct?

The test test_gradient_descent_matches_closed_form_on_project_data compares it with the exact least-squares solution θ1 = cov(x, y)/var(x), θ0 = ȳ − θ1·x̄. They agree to 6 significant digits. The closed form is used only in tests, never in the programs.

What do MAE, RMSE and R² tell you? (bonus)

MAE ≈ 558: average absolute error. RMSE ≈ 668: like MAE but punishing big errors more, which is why it is larger. R² ≈ 0.733: the line explains 73% of the price variation compared with always guessing the mean. §6

What does predict.py say for 500 000 km? Is that right?

A negative price (≈ −2 225), with a warning. The hypothesis is a straight line, so beyond about 396 000 km it crosses 0. We do not trust predictions far outside the training range (extrapolation). We show the value instead of hiding it, because that is what the specified hypothesis gives.

How would you improve the model?

More data; more features (age, brand, condition), which is multivariate linear regression; a non-linear model, since depreciation is curved; and a separate test set to measure precision on cars the model has not seen.

Code and tools

Why Python? Why these libraries?

The subject allows any language and recommends one that makes visualization easy. Python's standard library covers CSV, JSON and maths, so the mandatory part needs no external library. matplotlib is used only for the bonus plot.

What do the Makefile rules do? Does it relink?

make runs uv sync; clean removes caches; fclean also removes .venv and thetas.json; re is fclean + all. It does not relink: .venv is a file target that depends on pyproject.toml and uv.lock, so a second make prints “Nothing to be done”. Code walkthrough

Why is thetas.json not in the repository?

It is generated. Committing it would make predict.py appear trained before the evaluator runs train.py, which goes against the “theta0 and theta1 are 0 before training” rule.

What happens if thetas.json is corrupted?

load_thetas raises ModelError and the program prints a clear error. It does not silently fall back to 0, which would hide the problem. A missing file is different: it means untrained, so 0 is correct.
